# F002-B：任務編輯與軟刪除／封存規格

## 目的

讓 CEO 能編輯既有任務，並將任務軟刪除／封存。封存不刪除任務資料；一般任務清單及其篩選、排序結果只包含未封存任務。任何送出的標題或描述更新都重新經過 F002-A 本機脫敏閘道。

## 已核准範圍

- 新增 `PATCH /api/tasks/{task_id}`，可部分更新 `title`、`description`、`department`、`assigned_ai`、`priority`、`due_date`。
- 未提供的欄位保持原值；明確傳入 `description: null` 時儲存為 SQL `NULL`；空 patch 回 `422`。
- 更新的標題或描述須重新通過現有 `redact_text` 閘道；疑似候選未完成 CEO 決策前，不得更新任務。
- 沿用 F002-A 候選決策契約；保留原文必須附明確確認旗標。
- 新增 `PATCH /api/tasks/{task_id}/archive`，只標記封存時間，不硬刪除資料。
- 一般清單及所有篩選、排序均排除封存任務；已封存任務不得透過狀態更新 API 修改。
- 前端每筆任務提供編輯與封存入口；編輯表單預填目前值並支援儲存／取消；封存前明確確認，成功後依目前查詢重新載入。
- 加入 `tasks.archived_at` 可空時間欄位；未封存為 `NULL`，封存時寫入 UTC 時間。

## 排除範圍

不加入 `task_archive_events`、復原 API、復原 UI、封存搜尋、封存標記、批次操作、匯入匯出、永久刪除、資源回收桶、權限管理、多使用者、稽核儀表板、附件、多媒體、OCR、雲端 AI 或自訂脫敏規則。暫不為 `archived_at` 建索引。不修改 `package.json` 或新增依賴。

## API 契約草案

### `PATCH /api/tasks/{task_id}`

- 請求只接受核准的六個可更新欄位及 F002-A 的 `redaction_decisions`；未知欄位拒絕。
- 缺少欄位表示保留原值。`title` 若提供不可為 null 或空白；`description` 若提供可為 null，字串修剪後空白正規化為 null，最大長度 5,000。列舉與日期沿用建立任務 schema 驗證。
- 不含任何可更新欄位的空 patch 回 `422`；`status` 不在此 API 中。
- 每次成功回 `200 TaskRead`，回應沿用現有任務欄位，不公開 `archived_at`。
- 任務不存在或已封存時回 `404`；欄位驗證失敗、空 patch、過期／無效決策回安全 `422`。
- F002-A 疑似候選回結構化 `422`，只含欄位、位置、疑似類型與固定選項，不含候選原文。沒有完整決策前不修改任務。
- 保留原文決策未明確確認時拒絕更新。成功時只寫入脫敏後任務文字與不含原文的事件中繼資料。

### `PATCH /api/tasks/{task_id}/archive`

- 不需要本文；此端點本身只執行單筆封存，前端必須先取得使用者明確確認。
- 任務存在時設定 `archived_at` 為 UTC 現在時間並回 `204`。已封存任務重送仍回 `204`，保持冪等；不存在回 `404`。
- 不刪除任務或脫敏事件，不提供復原操作。

### 既有端點

- `GET /api/tasks` 在套用既有篩選與排序前先排除 `archived_at IS NOT NULL` 的任務。
- `PATCH /api/tasks/{task_id}/status` 對不存在或已封存任務均回 `404`；現有六種狀態及請求格式不變。

## 前端互動

- 每張任務卡片提供「編輯」與「封存」入口；不提供封存標記或封存搜尋。
- 編輯以目前核准欄位預填；儲存呼叫一般更新 API，成功後重載目前篩選／排序。取消不送出任何請求。
- 標題／描述候選沿用 F002-A 無原文提示、逐項決策、保留原文另行確認及伺服器重驗流程；候選未決定前不送出更新。
- 封存先顯示明確確認區，使用者可取消；成功後重載目前查詢，封存任務從所有一般結果消失。
- 請求失敗不得讓 UI 假稱已保存或已封存；保持可重試狀態並提供安全訊息。

## Migration 決策

- 新 revision：`0003_task_archiving`。
- `down_revision = "0002_task_metadata"`。
- `tasks.archived_at`：`DateTime(timezone=True)`，nullable，預設 `NULL`；不建立索引。
- upgrade 僅新增欄位，既有列保持未封存；不改動任務內容、狀態或脫敏事件。
- downgrade 不執行；依現有專案慣例拒絕自動降版，回復只以新建且驗證過的當下備份為準。
- Migration 檔案與合成資料庫測試屬準備工作；本規格不授權執行 migration。正式資料庫操作須取得另一筆 CEO 核准。

## 實作前置條件

實作前先建立新的正式工作資料庫備份，記錄完整路徑、大小及 SHA-256，並確認備份非空且雜湊可讀。若資料庫仍被程序持有或無法確保複製一致性，停止備份流程，先由 CEO 處理程序狀態；不得讀取資料庫內容或自行停止服務。
