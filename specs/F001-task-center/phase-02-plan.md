## 1. 目標與非目標

### 目標

- 新增任務時可設定下列欄位；`title` 沿用第一階段必填規則。
- 舊任務可在新清單正常呈現，新增選填欄位為空，優先級為 `MEDIUM`。
- 清單支援狀態、部門、負責 AI、優先級篩選，以及建立時間、更新時間、截止日、優先級排序。
- 表單與任務清單延續第一階段品牌、色系及版面結構，支援桌機與手機。
- 對任務標題及描述沿用同一後端 fail-closed 規則式脫敏服務。

### 非目標

- 編輯既有任務一般欄位；既有狀態變更仍可操作。
- 刪除、封存或 `ARCHIVED`；附件；搜尋；分頁；核准、退回原因、`NEEDS_REVIEW`、CEO 人工放行；登入、多人權限；AI 自動執行、雲端 AI 呼叫或 AI 活動紀錄。
- `created_by` 欄位；本階段新增欄位僅限本計畫第 2 節列明的五項。
- 將部門與 AI 對應實作為限制選項的規則。

## 2. 欄位、型別、必填性、預設值及驗證規則

資料庫與 API 欄位提案：

| 欄位 | 建議資料型別 | 必填／預設 | 驗證與呈現 |
|---|---|---|---|
| `title` | SQLite `TEXT`；API `string` | 必填；無預設 | 去除首尾空白；空白或缺漏回覆 422；送庫前經後端脫敏。 |
| `description` | SQLite `TEXT NULL`；API `string \| null` | 選填；省略或 `null` 均為 `null` | 純文字，不解析 HTML；最多 5,000 個字元，由後端驗證；空白輸入正規化為 `null`；送庫前經後端脫敏。 |
| `department` | SQLite `TEXT NULL`；API 固定代碼 enum 或 `null` | 選填；預設 `null` | 只接受第 3 節固定代碼；空值顯示「未指派」。 |
| `assigned_ai` | SQLite `TEXT NULL`；API 固定代碼 enum 或 `null` | 選填；預設 `null` | 只接受第 3 節固定代碼；空值顯示「未指派」；與部門不做硬性綁定。 |
| `priority` | SQLite `TEXT NOT NULL`；API enum | 選填；省略時 `MEDIUM` | 僅 `LOW`、`MEDIUM`、`HIGH`、`URGENT`；明確傳 `null` 回覆 422。舊任務遷移後為 `MEDIUM`。 |
| `due_date` | SQLite `DATE NULL`（以 `YYYY-MM-DD` 序列化）；API `date \| null` | 選填；預設 `null` | 僅接受真實日曆日期 `YYYY-MM-DD`；不接受時刻、時區或無效日期。 |

除 `priority` 外，選填欄位允許 `null`。建立時 `status` 仍由後端設為 `TODO`，不可由新增表單覆寫。保留既有 `id`、`created_at`、`updated_at` 欄位與 UTC 語意；不新增 `created_by`。`description` 經脫敏後才回傳及寫入。

`title` 沿用第一階段既有驗證規則。本計畫檢視到現行 Pydantic 驗證會先 `strip()`，並拒絕空白標題；本切片不調整此行為，也不擴張其限制。

## 4. UI 線框與操作流程

### 新增表單（沿用現有建立區塊，不改品牌與主版面）

桌機使用兩欄表單網格，避免所有欄位直向堆疊：

```text
新增任務
┌────────────────────────────────────────────────────────┐
│ 任務標題 *（跨兩欄）                                    │
│ 任務描述（純文字，可選；跨兩欄，多行輸入）              │
│ 部門（未指派／選項）       負責 AI（未指派／選項）       │
│ 優先級（預設 MEDIUM）       截止日（YYYY-MM-DD）          │
│ [負責 AI 僅為任務指派紀錄，目前未串接自動執行。]         │
│                                      [新增任務]           │
└────────────────────────────────────────────────────────┘
狀態／部門／AI／優先級篩選                         排序選單
任務列：標題與狀態操作；部門、AI、優先級、截止日、更新時間
```

欄位標籤與「未指派」選項要可見，不只依賴 placeholder。部門變更不會覆寫已選 AI；不自動預填 AI。提交時顯示儲存中，成功後清空表單並將新任務放入依目前篩選／排序規則計算的清單；若目前篩選不符合新任務，清單顯示無篩選結果，不可錯誤地強制插入。

### 操作流程

1. CEO 填寫必填標題及任意選填欄位；新建任務仍由後端設為 `TODO`。
2. 前端送出 `POST /api/tasks`；後端驗證代碼、日期與標題，對標題和非空描述呼叫同一脫敏閘道。
3. 後端只回傳脫敏後任務；無法安全分類時拒絕整筆任務建立。
4. CEO 以工具列組合篩選條件、選擇排序；改變狀態仍走原本操作。

### 任務列、長文字與狀態

- 標題允許換行，使用 `overflow-wrap:anywhere` 等換行方式，不以省略號隱藏必要內容。
- 部門、主要負責 AI、優先級、截止日及更新時間用清楚標籤／徽章呈現；未設定的選填欄位可顯示「未指派」或「未設定」，不得留白造成誤解。
- 描述預設最多顯示三行，超出時提供可鍵盤操作的「顯示更多／收合」按鈕；不建立編輯既有任務的操作。
- 顯示指定文案：**「負責 AI 僅為任務指派紀錄，目前未串接自動執行。」** 不顯示虛構連線、AI 進度或活動。
- 保留六種現有狀態選單與更新回復行為；`REVIEW` 仍只表示狀態，不加入核准／放行按鈕。

### 載入、空白、錯誤與不同螢幕

- 初次載入顯示清單載入狀態；請求失敗顯示可理解錯誤及重試操作。
- 無任務時顯示既有空清單引導；有任務但篩選無結果時顯示「沒有符合條件的任務」及「清除篩選」。
- 欄位驗證錯誤貼近表單欄位；脫敏拒絕訊息不得包含原始輸入。篩選／排序載入失敗保留現有列表並顯示錯誤。
- 桌機（建議驗收寬度 1280 px）：表單兩欄、篩選排序同列、任務資訊分組顯示。
- 手機（建議驗收寬度 375 px 及 320 px）：表單選填控制以兩欄或緊湊分組呈現，必要時工具列換行；任務列可換行，狀態控制保持易點選，不產生水平溢出。
- 沿用目前色系、品牌與導覽；不加入動畫或辦公室模擬畫面。

## 5. API 變更

### `POST /api/tasks`

請求欄位：

```json
{
  "title": "必填標題",
  "description": "可選純文字或 null",
  "department": "DEVELOPMENT",
  "assigned_ai": "CODEX",
  "priority": "MEDIUM",
  "due_date": "2026-12-31"
}
```

`description`、`department`、`assigned_ai`、`due_date` 可省略或傳 `null`；`priority` 省略時為 `MEDIUM`，明確傳 `null` 回覆 422。`description` 最多 5,000 字元，由後端驗證，純空白正規化為 `null`。請求不接受 `status`，伺服器建立為 `TODO`。201 回應包含既有欄位及以上脫敏後的新欄位。空白標題、超長描述、未知代碼、非法優先級／日期回覆 422。`title` 沿用第一階段驗證，不在本計畫或第一切片改動。

如標題或描述有可辨識敏感值，回應只含遮蔽後值，並寫入現有無原文脫敏中繼紀錄；若任一欄位無法判定，回覆 422 且不建立任務，錯誤內容與日誌不得回顯原文。

### `GET /api/tasks`

新增單值可選查詢參數：

| 參數 | 值 |
|---|---|
| `status` | 六種既有 `TaskStatus` 之一 |
| `department` | 第 3 節部門代碼之一 |
| `assigned_ai` | 第 3 節 AI 代碼之一 |
| `priority` | `LOW`、`MEDIUM`、`HIGH`、`URGENT` |
| `sort_by` | `created_at`、`updated_at`、`due_date`、`priority` |
| `order` | `asc`、`desc`；預設 `asc` |

不同篩選條件以 AND 組合；每種條件第一版只選一個值。參數省略時不篩選；不支援搜尋、分頁或自由排序欄位。非法查詢值回覆 422。排序詳見第 6 節。回應中的日期為 `YYYY-MM-DD`，時間欄位仍為 UTC `Z` 格式。

### 保持不變的端點與錯誤

- `PATCH /api/tasks/{task_id}/status` 保持既有請求與六種狀態驗證，不新增轉換／角色規則。
- 任務不存在的狀態更新仍回覆 404；不新增一般欄位 `PATCH`、刪除、審核、退回、附件或 AI 執行 API。
- 請求錯誤不回顯敏感原文；伺服器不得記錄完整請求本文。後續欄位／API 整合切片需使用實際 HTTP 請求測試同時含合成敏感標題／描述與非法代碼、非法日期、型別錯誤、脫敏拒絕的各種路徑；回應與捕獲日誌不得含原始標題、描述或完整請求本文，不能只直接測 `UncertainSensitiveData`。
- 特別覆蓋驗證優先順序：同一個合成請求同時含敏感標題／描述及非法代碼、非法日期、型別錯誤或脫敏拒絕時，錯誤回應與日誌均不得回顯原始標題、描述或完整請求本文。後續欄位／API 整合切片必須用實際 HTTP 請求與捕獲日誌測試，不可只測脫敏例外類別。

## 6. 篩選與排序的具體規則

- 篩選欄位：狀態、部門、主要負責 AI、優先級。各欄預設「全部」；各欄最多選一項，多欄同時選擇時採 AND。
- 清單計數以篩選後結果為準；「清除篩選」清空四種條件，保留目前排序。
- 排序欄位：建立時間、更新時間、截止日、優先級；允許升冪／降冪切換。
- 預設 `sort_by=created_at&order=asc`，延續第一階段目前由舊至新的建立時間排列。
- 時間依資料庫 UTC 值比較，不依前端格式化後的台北時間字串排序。
- 截止日按日曆日期排序；未設定截止日的任務在升冪與降冪都固定排在最後。
- 優先級順序定義為 `LOW < MEDIUM < HIGH < URGENT`；升冪為低至高，降冪為緊急至低。
- 同值結果以 `created_at ASC`，再以 `id ASC` 作穩定次排序；無分頁，後端先篩選及排序再回傳完整結果。
- 前端篩選條件變更時取消或忽略較舊的在途查詢，避免舊回應覆蓋新結果；失敗時保留目前可見資料並允許重試。

## 7. 資料結構升級與還原方案

### 升級策略提案

現況 `create_all()` 只建立缺少的表，不會替舊 `tasks` 表補欄位；不可只依賴它做本次升級。採用 Alembic 及必要遷移設定；不得順便升級無關套件。

對既有 `tasks` 表使用 SQLite 原生 `ALTER TABLE ... ADD COLUMN`，不刪表、不重建表、不重寫既有列：

- `description TEXT NULL`
- `department TEXT NULL`
- `assigned_ai TEXT NULL`
- `priority TEXT NOT NULL DEFAULT 'MEDIUM'`
- `due_date DATE NULL`（SQLite 以 ISO `YYYY-MM-DD` 儲存）

遷移不得更新舊列的 `id`、`title`、`status`、`created_at`、`updated_at`；舊列新增欄位為 `NULL`，`priority` 由資料庫預設值補為 `MEDIUM`。保留 `redaction_events` 及既有列。新欄位的代碼與日期驗證仍由 Pydantic 負責；不可用 SQLite 重建表引入超出範圍的轉換。

空資料庫透過從空庫開始的遷移建立完整 schema。對沒有版本標記的舊庫，遷移工具先檢查它符合目前第一階段 schema（`tasks` 五個既有欄位及 `redaction_events` 七個既有欄位），再標記為舊版基線後升級；schema 不符、版本未知或檢查失敗時停止，不自動 `create_all()` 修補或覆蓋。合成舊庫須含六種既有任務狀態各至少一筆，並驗證所有列和脫敏紀錄逐欄保留。

遷移工具使用明確 `--database-path` 引數且不得省略；只操作該參數指定路徑，不讀環境變數、不回退到工作資料庫。空庫初始化也必須指定測試路徑。工具拒絕未知 schema。第一個切片不改變現有應用啟動行為；「未升級 schema 時阻擋服務啟動」延至後續欄位與 API 整合切片。

### 合成舊版資料庫驗證

測試只在測試暫存目錄建立合成 SQLite 檔案，結構仿照第一階段 `tasks` 與 `redaction_events`，任務列涵蓋 `TODO`、`IN_PROGRESS`、`REVIEW`、`BLOCKED`、`RETURNED`、`DONE` 六種既有狀態各至少一筆，並放入至少一筆不含原文的脫敏事件。升級後驗證：

1. 舊任務 `id`、`title`、六種 `status` 中的原值、`created_at`、`updated_at` 逐筆不變。
2. 舊任務新欄位為 `description=NULL`、`department=NULL`、`assigned_ai=NULL`、`due_date=NULL`、`priority='MEDIUM'`。
3. `redaction_events` 原列與欄位值保留，沒有敏感原文欄位。
4. `PRAGMA integrity_check` 回覆 `ok`，且應用可列出舊任務。
5. 升級已到目標版本後再次執行不會新增／重建欄位或改動資料。
6. 另以合成空資料庫驗證完整建表及遷移失敗路徑；用未知表／欄位 schema 驗證遷移以非零狀態安全停止且原 schema、資料保持不變。
7. 對合成舊庫使用 SQLite Online Backup API 備份，驗證備份完整性；破壞測試目標後從備份還原，逐欄確認舊版 schema、六種狀態任務及脫敏紀錄均恢復，不以 `integrity_check` 單獨作為還原成功依據。測試絕不使用 `.task-center/`。

### 正式升級前備份、失敗與還原

1. 先經 CEO 對實作及正式資料庫操作另行授權；本切片不讀取、備份、遷移或還原工作資料庫。
2. 停止後端，確認沒有連線寫入；用 SQLite Online Backup API 將資料庫備份至使用者指定的安全位置，避免只複製仍有 WAL 寫入的主檔。
3. 對來源與備份執行 `PRAGMA integrity_check`；記錄備份位置、大小、時間與雜湊，不記錄資料列或敏感值。驗證備份前不可開始遷移。
4. 經另行授權後才對指定正式資料庫執行版本化遷移；遷移後檢查版本、欄位、`PRAGMA integrity_check`、舊任務關鍵欄位保留及 API 冒煙測試。
5. 任一步失敗即停止服務、保留失敗資料庫以供調查，不繼續服務或刪除失敗檔。由 CEO 決定還原後，先將失敗檔另存，再從已驗證備份還原至原路徑；還原後再次執行完整性檢查及舊任務檢查。
6. 備份保留至 CEO 驗收與明確清理指示；本計畫不授權自動刪除備份或直接操作工作資料庫。

## 8. 脫敏及錯誤處理

- `title` 與非空 `description` 各自呼叫現有 `redact_text(text, field_name)`；不另建較寬鬆的第二套規則。
- 已辨識敏感資料按目前佔位符遮蔽並寫入原始長度、遮蔽類型、原始輸入位置及時間等中繼資料；不得保存原始值。
- 任一欄位拋出 `UncertainSensitiveData` 時，拒絕整筆建立，回覆 422 通用訊息，不回顯敏感候選值；若已有不確定紀錄，僅保存其脫敏中繼資料。
- 同一請求兩欄都檢查完成前不得寫入任務列，避免標題成功後描述失敗卻留有半筆任務。已辨識的遮蔽結果可以回傳，但只能在安全建立成功後回傳。
- `description=null` 或正規化後空白時不執行文字掃描；原始中繼長度與位置都以各欄位的原始文字計算，不以替換後文字計算。
- 不把請求本文、原始標題／描述或例外物件寫入應用日誌；測試以合成敏感字串掃描任務表、脫敏紀錄及捕獲日誌，確認沒有原始字串。
- 驗證失敗回覆 422；不存在任務維持 404；資料庫或不可預期錯誤回覆通用訊息並記錄不含請求內容的錯誤資訊。

## 9. 驗收條件與測試案例

### 後端 API／資料

- 建立有效任務可含各選填欄位；回應和資料列的 `status=TODO`，省略優先級時為 `MEDIUM`。
- 標題空白或缺漏拒絕；description 可省略、為 null 或純文字。
- 合法部門／AI／優先級／日期可儲存並正確回傳；未知代碼、非法日期（如 `2026-02-30`）、日期時間字串拒絕。
- `description` 中合成 Email／手機等已辨識值被遮蔽，事件的 `field_name=description` 且不存原值。
- 不確定描述拒絕整筆任務；資料庫無任務列，事件僅有中繼資料，回應及日誌不含合成原文。
- status 查詢、department、assigned_ai、priority 各自有效篩選；多條件 AND；無結果回空陣列；非法參數 422。
- 建立時間、更新時間、截止日、優先級四種排序皆驗證升冪／降冪、同值穩定次序及截止日 null 固定最後。
- 原本狀態更新六值、更新時間、404 行為維持第一階段；清單排序預設維持 `created_at ASC`。

### 資料遷移

- 依第 7 節以合成舊版資料庫測試保留、預設值、重複執行與 `integrity_check`。
- 用合成故障遷移確認服務停止、失敗檔保留、可由已驗證備份還原；不可連到工作資料庫。
- 空資料庫初始化後結構與既有資料表完整。

### 前端／GUI

- 必填標題、預設 `MEDIUM`、部門與 AI「未指派」、截止日期格式、描述與全部值正確送入 API。
- 脫敏拒絕顯示通用訊息，不呈現或留存使用者輸入的敏感原文；其他欄位驗證錯誤可理解。
- 清單顯示部門、AI、優先級、截止日、狀態與更新時間；AI 說明文案逐字正確，不顯示虛構執行資料。
- 篩選／排序會呼叫正確查詢參數；組合篩選、清除篩選、空清單、無結果、載入、錯誤及重試均可使用。
- 狀態更新仍可操作，失敗時回復舊值；沒有既有欄位編輯、刪除、核准、退回或 AI 啟動操作。
- 長標題可換行，長描述可展開／收合；桌機 1280 px、手機 375 px 與 320 px 手動檢查無水平溢出且主要控制可操作。
