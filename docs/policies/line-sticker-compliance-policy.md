# LINE 貼圖合規政策

- 政策編號：LINE-COMP-001
- 版本：1.0
- 生效日：2026-11-15
- 政策負責人：CEO
- 維護單位：法律部門
- 規範來源核對日：2026-11-15（Asia/Taipei）

## 1. 目的

確保公司為 CEO 的 LINE 貼圖副業進行創作、生成、批次處理、格式整理、品管、上架與收支管理時，以 LINE Creators Market 官方網站現行規範及適用法律為準；由開發、法律、品管、財務四部門共同執行檢查，留下可追蹤證據，避免規範更新或部門交接造成遺漏。

本政策是內部作業控制，不保證 LINE 必然核准作品，也不取代法律專業意見或平台審查。

## 2. 適用範圍

適用於公司人員、受託人及公司使用的工具，凡涉及下列事項均須遵守：

- LINE 靜態貼圖與其主圖、聊天室標籤圖、標題、創作者名稱、說明及著作權文字。
- 使用生成式 AI 或其他工具產生、修改、挑選、組合或翻譯貼圖內容。
- LINE 靜態貼圖批次生成工具，以及檔案命名、尺寸整理、色彩／透明度處理、打包與上傳前檢查工具。
- 權利確認、平台送審、定價、發布、收入與相關紀錄。

政策涵蓋工具產出的素材與最終成品；使用 AI、模板、外包或自動化不會減免人工審查及權利確認責任。非 LINE 產品僅在其成果預計用於 LINE Creators Market 時適用本政策。

## 4. 責任單位

| 單位 | 必要責任與交付證據 |
|---|---|
| 開發部門 | 維護生成、批次生成及格式整理工具；將每次產出的工作批次 ID、工具版本、採用的官方規格版本／核對日、輸入來源識別、輸出檔清單及自動檢查結果留存。不得把工具通過視為內容、權利或法律審查通過；不得靜默覆寫原始檔。規格變更時修正檢查設定並提供測試證據。 |
| 法律部門 | 政策與官方來源登錄表負責人；確認適用條款、著作權／商標／肖像／隱私等權利依據、授權範圍、必要同意及法律風險；判讀更新影響，發布通知並決定是否暫停受影響作品。爭議或不確定事項須升級 CEO，不能由工具或開發自行放行。 |
| 品管部門 | 對每套作品及其上架文字執行內容與技術檢查；確認生成結果與核准方向一致、無未檢素材、缺圖、重複或錯誤輸出；抽查之外，對提交包的所有檔案執行必要格式檢查並留下清單、結果及覆核人。確認平台規格與工具檢查設定一致。 |
| 財務部門 | 在發布／定價前確認售價、適用地區、平台收入分配與費用資訊、收款及稅務資料處理；只使用官方現行資料和 CEO 核准的帳務設定。不得將財務核對當成權利或內容核准；付款資料限權存取，不放入一般作品或測試紀錄。 |
| CEO | 核准政策例外及重大商業／風險決策；收到規範重大變更、法律爭議、疑似違規或平台處分通知後決定是否停用、撤回、申訴或採取其他措施。 |
| 作品負責人 | 為每個作品批次指定負責人，確保需求、素材來源、審查證據與發布版本可對應；未完成四部門必要檢查不得送審或發布。 |

同一人兼任多個部門角色時仍須完成各項檢查並逐項記錄；高風險權利判斷及發布核准不得只以同一人未留紀錄的口頭確認代替。

## 5. 作品合規流程與放行閘門

每個貼圖作品集建立唯一作品／批次識別碼，並按以下順序執行：

1. **建立需求與來源清單（作品負責人／開發）：** 記錄用途、目標地區、作品類型、需產生的檔案與文字欄位；列明每個自有、委託、素材庫、第三方或 AI 生成素材的來源、授權依據及允許用途。不得將「網路可取得」或「AI 生成」視為已取得商用權利。
2. **核對現行規範（法律／開發）：** 法律確認適用官方來源及特別條款；開發將該次核對日期及規格版本／快照識別附於批次紀錄。若規格不能確定、來源頁面不可用或規範互相衝突，暫停該作品，不以舊版工具結果放行。
3. **生成與批次整理（開發）：** 只使用核准來源和工具；保留輸入與輸出間的檔名／識別對照及處理紀錄。批次工具應可重現檢查結果，不得無記錄地替換作品內容、裁切關鍵元素、移除權利資訊或放寬限制。工具自動修正後仍須人工檢查實際輸出。
4. **權利與內容檢查（法律）：** 確認作品及文字不侵害他人權利，照片／肖像有可證明的合法依據與必要同意，素材授權涵蓋修改、商業利用及 LINE 上架所需範圍；確認無違法、歧視、誹謗、侵害隱私、未授權角色／品牌或其他高風險內容。無法證明權利時不得使用。
5. **技術與內容品管（品管）：** 對提交包逐檔核對數量、檔名、格式、尺寸、檔案大小、透明背景、偶數尺寸、解析度、RGB 色彩及可讀性；依作品當下適用的官方規格核對主圖、聊天室標籤圖、貼圖張數、標題、創作者名稱、說明、著作權文字及彼此一致性。確認無拼字錯誤、重複圖、缺漏、損壞、過度相似或不適合日常溝通的組合。不得只驗收抽樣檔而漏掉其他檔案。
6. **財務檢查（財務）：** 核對發布地區、可選價格、平台費用／收入分配、稅務與收款資料；使用官方最新條件並記錄來源及查核日期。數字或條款無法確認時不得對外承諾收益或完成發布設定。
7. **送審與發布放行（作品負責人）：** 只有法律、品管、財務各自留下通過紀錄後才可送審。平台退件或要求修改後，回到受影響的檢查步驟；任何內容、素材、文字、格式或地區變更都要重新檢查。平台核准不等同公司內部流程自動完成；發布前由作品負責人確認核准版本與預定發布版本一致並留存證據。
8. **結案留存（作品負責人／法律）：** 留存提交版清單、工具與規格版本、來源和授權證據位置、四部門結果、送審／退件／核准／發布狀態及日期。不得把密碼、金鑰、客戶個資或不必要的付款憑證放進紀錄；敏感授權文件依公司限權規則保存。

### 5.1 上架前檢查項目

每批至少確認並記錄以下結果（通過／不適用並說明／阻擋）：

- **官方規格：** 提交日已重新檢查官方靜態貼圖頁面；所有圖檔、數量、尺寸、大小、格式、色彩、透明度、解析度與文字欄位均符合當日適用要求。規格變更後不可沿用舊版檢查設定。
- **內容審查：** 依當日 Review Guidelines 檢查違法或有害內容、暴力／色情／歧視、仇恨、個資、騷擾誹謗、廣告、募款、其他通訊服務提及及平台其他禁止／不建議內容。
- **權利證明：** 每項非完全自有素材均有來源、授權文件或可查證依據；肖像、商標、字型、音效或其他第三方元素的使用範圍已確認。缺證據即阻擋。
- **文字與一致性：** 標題、創作者名稱、說明與著作權文字符合限制、無錯字，且與實際圖像相符；不含未核准 URL、促銷資訊或平台禁止的內容。
- **批次完整性：** 生成數量與預期相符；提交清單中的每個檔案均存在、可開啟且已檢查；沒有暫存、草稿、私人資料、未核准素材或錯誤版本混入。
- **部門簽核：** 開發記錄工具／規格版本及檢查；法律記錄權利與內容判定；品管記錄逐檔結果；財務記錄價格、費用、收入與收款檢查。必要欄位缺漏即不放行。

本政策建立時官方靜態貼圖頁面列有：主圖 1 張 240×240、貼圖 8／16／24／32／40 張且每張最大 370×320、聊天室標籤圖 1 張 96×74；提交圖像 PNG、偶數尺寸、至少 72 dpi、RGB。這些數值僅為 2026-11-15 的核對快照，**不得取代每次提交前重新查閱官方頁面**；若現行官方頁面不同，採適用的最新官方規格並更新工具設定與本批核對紀錄。

## 6. 規範來源版本追蹤與更新通知

### 6.1 來源登錄及例行檢查

- 法律部門至少每月檢查一次第 3 節所有官方來源及適用的 Creator 通知；每次送審前，作品負責人另須重新確認相關頁面。
- 登錄每次檢查的來源 ID、完整 URL、頁面語言／地區、查核時間、頁面明示更新日或「未標示」、檢查人、內容差異摘要、影響作品類型、判定與證據位置。若沒有官方版本號，不得自行編造版本號；以查核時間及公司保存的頁面快照／摘要識別該次版本。
- 法律部門保存更新前後可比較的官方頁面快照或不違反網站條款的必要摘錄；記錄差異及內部判斷，不大量複製或重新發布 LINE 內容。快照須標示來源、擷取日期與保存人。
- 開發部門維護格式規則、測試案例與工具版本對應表。每次規格更新後，須以合成檔案測試新規則、舊規則差異及拒絕案例，並由品管確認再部署；未確認前停止受影響類型的批次輸出與送審。

### 6.2 通知與變更處置

1. 法律部門發現任何官方頁面、條款、公告或帳號通知改變後，於一個工作日內在公司核准的工作公告管道通知開發、品管、財務、作品負責人及 CEO，附來源 ID、查核日期、變更摘要、暫行措施與需回覆期限；緊急或可能影響權利／違法性的變更應立即通知並要求暫停受影響活動。
2. 開發、品管及財務收到通知後，於三個工作日內回覆各自影響評估、受影響工具／作品／價格設定與建議處理。法律部門彙整為「需立即停用／阻擋」、「需修正後重驗」或「無需變更（附理由）」；重大或無法判定事項交 CEO 決定。
3. 被判為受影響的批次，在規則、工具與檢查表更新並完成重驗前，不得生成最終提交包、送審或發布。法律部門通知受影響作品負責人及 CEO；若已上架，立即評估暫停銷售、下架、修改或聯絡平台的必要性。
4. 更新完成後，法律部門更新來源登錄及政策版本紀錄；開發更新工具規格映射；品管重跑受影響檢查；財務重核變動的價格、費用或收益條件。通知須標記結案日期與未完成事項負責人。

## 7. 紀錄與驗收

每個作品批次均須有可定位的合規紀錄，至少包含：作品／批次識別碼、負責人、作品類型與目標地區、官方來源查核日及證據位置、工具／規格版本、素材權利證據位置、逐檔品管結果、法律與財務結論、送審與平台回覆狀態、發布版本及日期、缺失與結案人。

政策執行的可驗收條件：

- 四部門責任人均已指派，且每批必要檢查有具名紀錄及日期。
- 每月來源檢查與每次送審前檢查可由登錄表及批次紀錄證明。
- 每個提交檔案都可對應檢查結果；任何權利證據缺失、規格失配或未決法律疑慮均阻擋送審／發布。
- 官方更新通知符合時限，受影響工具有測試證據、受影響作品有處置紀錄。
- 財務條件有官方來源與查核日期，無未確認的價格、費用或收入承諾。
- 紀錄不含登入憑證、金鑰、非必要個資或正式資料庫內容。

法律部門每季抽查至少一個近期作品批次；若當季無新批次，檢查來源登錄、工具規則測試與更新通知紀錄。抽查發現缺漏時建立缺失項目、指定責任人與期限，追蹤至完成。

## 8. 例外處理

- 不允許以時間急迫、AI 已生成、工具通過、過去曾核准或平台曾核准作為跳過法律、品管或財務檢查的理由。
- 官方來源無法存取、版本語言衝突、權利文件不完整、規格不明或內容可能涉及違法／侵權時，將批次標記為「阻擋」，保留安全的錯誤與來源資訊，不上傳、不發布；法律部門確認後才可解除。
- 因平台個別通知或特殊合作規則須偏離一般流程時，由法律部門提出書面風險說明與限制，CEO 書面核准後才可採例外。例外須列明作品、範圍、期限、依據、核准人、補償控制及結束條件；不得豁免適用法律或平台明文禁止事項。
- 生成工具或整理工具誤刪、覆寫或混入檔案時，立即停止該批處理，保留輸入／輸出識別與錯誤紀錄，通知開發與品管；確認來源完整、修正工具並重新逐檔驗收後才能恢復。

## 9. 違規及平台處分處理

疑似違規、侵權主張、平台退件／限制／下架通知、未授權素材或錯誤發布一經發現：

1. 發現者立即通知法律部門、作品負責人及 CEO；保存通知、作品版本、提交紀錄及相關權利文件，不刪改證據。
2. 法律部門評估適用條款、法規、權利主張及通知期限；作品負責人立即暫停受影響素材的生成、送審、宣傳或發布。可能持續侵害或涉及個資時，優先限制公開存取並由法律部門決定聯絡平台及後續處置。
3. 開發部門停用問題規則或工具版本，保留可重現的安全測試證據；品管確認受影響作品範圍並重查同批輸出；財務評估退款、收入、費用或報稅影響並限制相關帳務資料存取。
4. CEO 決定下架、修改、申訴、退款、停止相關工具或其他補救措施。未收到書面處置決定前，不得重新發布受影響版本。
5. 法律部門建立事件紀錄：事件編號、發現時間、涉及批次／工具版本、規範來源、影響範圍、立即措施、負責人、CEO 決定、改善期限及結案證據。不得將第三方機密、帳密或不必要個資複製進事件紀錄。
6. 完成根因檢討；更新來源、規格檢查、工具測試或部門訓練，並確認同類風險已納入後續批次驗收。
