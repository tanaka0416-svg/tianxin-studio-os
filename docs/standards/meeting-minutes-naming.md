# 會議記錄編號與歸檔命名標準

- 標準編號：MEET-NAME-001
- 版本：1.0
- 建立日：2026-11-15
- 標準負責人：文件庫管理人
- 執行單位：秘書／記錄人；主持人確認

## 1. 目的

為每場實際召開的會議提供唯一、可搜尋、可配對的識別碼、檔名與歸檔結構，讓精簡版、詳細版及其附件可共同追溯，避免同名覆寫或版本混淆。

## 2. 範圍

適用於公司會議登記表、精簡版、詳細記事版、附件索引及更正版本。實際會議記錄屬內部文件，應保存於公司核准且限權的文件庫；本專案儲存庫只保存本標準與空白範本，不得預設為實際會議記錄存放處。

## 3. 責任單位

- **秘書／記錄人：** 查閱當日流水登記、分配編號、使用正確檔名與資料夾、維護配對連結和版本索引。
- **主持人：** 確認實際會議日期、基本資料及定稿配對。
- **文件庫管理人：** 維護唯一編號登記表、日期資料夾、權限、搜尋欄位及版本保存。
- **法律／隱私負責人：** 指定需限制存取、法律保留或不得一般化保存的資料處置方式。

## 4. 編號與命名流程

1. 會議排定時，由秘書按當地會議日期先行查登記表並保留流水序號；實際召開後確認日期、開始時間和編號一致。
2. 會議編號採 `MEET-YYYYMMDD-NN`：`YYYYMMDD` 為會議實際開始日期，時區使用會議通知指定時區，未指定時預設 `Asia/Taipei`；`NN` 為當日依預定開始時間順序分配的兩位流水號 `01` 至 `99`。
3. 同日超過 99 場時，當日後續編號以三位流水號延伸（`100` 起），不得重用已分配編號。登記表保留排序時間及分配人，以供稽核。
4. 兩份記錄使用完全相同會議編號；精簡版與詳細版只以版本類型字尾區分。建議檔名：

   - `MEET-YYYYMMDD-NN_YYYYMMDD_brief_v01.md`
   - `MEET-YYYYMMDD-NN_YYYYMMDD_detailed_v01.md`

   檔名第二個日期為建立／確認日期；文件內容的會議日期仍填實際會議日期。已確認後的更正版本遞增版本號，如 `v02`，不得覆寫前版。

5. 資料夾採 `會議記錄/YYYY/YYYY-MM/MEET-YYYYMMDD-NN/`；同一會議所有版本與附件索引放在同一資料夾。機密附件可存於更嚴格的受控位置，以附件索引記錄識別碼及權限。
6. 建檔後在登記表記錄會議編號、會議名稱、會議日期、主持人、記錄人、狀態、精簡版位置、詳細版位置、確認日期、最新版本與存取等級。

## 5. 檢查項目

- [ ] 編號符合格式，日期使用實際會議開始日，NN 當日唯一且未被重用。
- [ ] 配對兩份的會議編號、實際會議日期、時間／時區、參與者、主持人及記錄人一致。
- [ ] 檔名類型字尾正確（brief／detailed），版本號一致於文件內容，無覆寫歷史檔案。
- [ ] 兩份記錄位於同一會議資料夾，登記表連結有效且可搜尋。
- [ ] 附件索引可追溯文件名稱、版本、日期、來源、權限與議程／決議關聯。
- [ ] 歸檔位置為核准文件庫，權限依機密等級設定；未將實際內容放入不適當的公開或程式碼位置。
- [ ] 取消／改期會議保留登記狀態且不重用舊編號；改期會議採實際日期的新編號。

## 6. 例外處理

- **改期：** 原預留編號在登記表標示「改期／未召開」，不沿用；依新日期重新分配編號。
- **取消：** 保留編號和取消狀態、日期及通知人，不建立決議記錄、不重用編號。
- **日期跨日：** 以會議實際開始日及通知指定時區計算；同一場會議不因跨午夜更改編號。
- **缺少登記或重複編號：** 暫停定稿歸檔，由文件庫管理人查登記表並分配唯一號碼；保留修正前後映射，不能靜默改名。
- **已定稿更正：** 新版遞增 `vNN`，保留前版並填更正原因、提出人、核准人、日期及受影響文件；共同資訊改動須同步更新兩種版本。
- **無法存入一般文件庫：** 由文件庫管理人與法律／隱私負責人指定受控存放位置，登記表只保留受控識別碼與權限說明。
- **超過 99 場／其他命名限制：** 使用三位序號延伸並在登記表註明；若文件庫限制檔名，先保留標準編號於中繼資料與登記表，再由管理人記錄等效檔名映射。

## 7. 驗收與維護

每月抽查新增會議登記資料與歸檔配對，確認唯一性、命名、版本、連結與權限；缺失記錄責任人及完成期限。文件庫管理人每年檢討一次本標準，若文件平台、保存政策、隱私規範或會議制度變更則提前修訂。
